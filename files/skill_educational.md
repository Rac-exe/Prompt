# SKILL FILE: EDUCATIONAL

## WHEN TO USE THIS SKILL

Use this skill when the request involves:
- Writing tutorials or how-to guides
- Explaining complex concepts to beginners
- Creating course content or lesson plans
- Writing documentation with teaching intent
- Onboarding materials or training guides
- Study guides, explainers, or summaries

**Keywords that trigger this skill:**
tutorial, explain, teach, learn, guide, course, lesson, training, education, beginner, step by step, how to, introduction, overview, explainer, walkthrough

---

## OPTIMIZATION CHECKLIST

✓ **Audience Level?**
  - Complete beginner, intermediate, or advanced?
  - Domain background (programmer, non-technical, student)?

✓ **Learning Objective?**
  - What should the reader know/be able to do after?
  - What misconceptions to address?

✓ **Format?**
  - Step-by-step guide, narrative explanation, reference doc?
  - Include examples? Code? Analogies?

✓ **Depth?**
  - Surface understanding or deep dive?
  - Scope: single concept or full topic?

---

## OPTIMIZATION TEMPLATE

```
You are an expert [subject matter expert] and experienced educator.

CONTEXT:
Topic: [specific concept or skill]
Audience: [knowledge level and background]
Goal: [what learner will understand/do after reading]

TASK:
[Exact educational deliverable]

REQUIREMENTS:
- Level: [Beginner | Intermediate | Advanced]
- Tone: [Encouraging / Neutral / Academic]
- Format: [Step-by-step / Conceptual / Mixed]
- Length: [word count or number of sections]
- Include: [examples / analogies / code / diagrams description]
- Avoid: [jargon without explanation / assumed knowledge]

STRUCTURE:
1. Hook — Why this matters (real-world application)
2. Core concept — Simple explanation first
3. Examples — Concrete, relatable
4. Deeper dive — How/why it works
5. Common mistakes — What to avoid
6. Summary + Next steps

SUCCESS CRITERIA:
- A [target learner] can understand and apply this immediately
- No unexplained jargon
- At least one concrete example per concept
```

## COMMON IMPROVEMENTS

### ❌ BAD:
```
"Explain how APIs work"
```

### ✅ GOOD:
```
You are a software educator who specializes in explaining technical concepts to non-programmers.

TASK:
Explain what APIs are and how they work for someone with no programming background.

AUDIENCE:
- Non-technical professional (marketer, product manager)
- Comfortable with apps and websites but not code
- Needs to understand APIs to communicate with developers

REQUIREMENTS:
- Tone: Conversational, encouraging, avoid jargon
- Format: Starts with relatable analogy, then builds to technical
- Length: 400-600 words
- Must Include:
  - Real-world analogy (restaurant menu, electrical outlet, etc.)
  - At least 2 concrete everyday examples of APIs they already use
  - What "calling an API" means in plain language
- Must Avoid: Code snippets, HTTP methods, JSON syntax at first mention

STRUCTURE:
1. Relatable analogy to make the concept click
2. Two everyday examples (weather app, Uber, etc.)
3. Simple definition in one sentence
4. What it means when developers say "use the API"
5. Why it matters to them

SUCCESS CRITERIA:
- Reader can explain what an API is to a colleague after reading
- No follow-up explanation needed
- Doesn't feel technical or intimidating
```

## DOMAIN-SPECIFIC TIPS

### For Technical Tutorials:
- Prerequisites section at start
- Working code examples > pseudocode
- Common errors section
- "What you'll build" at the top

### For Concept Explanations:
- Simple analogy first, technical definition second
- Build from known to unknown
- One concept per section

### For Courses/Lessons:
- Learning objectives at start (measurable)
- Check for understanding at end
- Progressive difficulty

---

## ANTI-PATTERNS TO AVOID

❌ Don't explain to experts with beginner framing
❌ Don't use jargon without defining it first
❌ Don't skip examples — theory without examples doesn't stick
❌ Don't make it too long — break into digestible chunks
