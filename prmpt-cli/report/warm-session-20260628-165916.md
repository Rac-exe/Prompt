# Warm-Session Benchmark Report

Run: `warm-session-20260628-165916`

This run tested the concern that the original cold benchmark may overstate PRMPT's advantage because every prompt started from a fresh agent session. Here, each repo/repeat used one copied workspace and ran prompts in order: `p1 -> p2 -> p3`.

## TLDR

PRMPT still saves tokens in the warmer user-flow setup.

| Arm | Score | Tokens | Avg Tokens/Turn | Total Time | Avg Speed | Token Delta vs Claude |
|---|---:|---:|---:|---:|---:|---:|
| Claude A raw | `27/27` | `10,042,422` | `371,942` | `62.98 min` | `139.9s` | baseline |
| PRMPT B raw | `27/27` | `6,561,817` | `243,030` | `39.94 min` | `88.8s` | `34.7% less` |
| PRMPT C optimized | `25/27` | `3,322,867` | `123,069` | `35.27 min` | `78.4s` | `66.9% less` |
| Cursor raw | `27/27` | `9,990,378` | `370,014` | `28.06 min` | `62.4s` | `0.5% less` |
| Codex raw | `27/27` | `22,932,484` | `849,351` | `50.94 min` | `113.2s` | `128.4% more` |

Best reliable PRMPT arm: **B**. It matched Claude/Cursor/Codex correctness at `27/27`, while using `34.7%` fewer tokens than Claude and finishing `36.6%` faster.

Cheapest arm: **C**. It used `66.9%` fewer tokens than Claude, but missed 2 turns, both on `nova-p1`.

## Benchmark Shape

- Workload: `3 repos x 3 prompts x 3 repeats = 27 turns per arm`.
- Total evaluated turns: `135`.
- Workspace reset happened once per repo/repeat flow, not once per prompt.
- Within each flow, the same workspace carried forward from `p1` to `p2` to `p3`.
- Verification ran after every turn using each task's `npm test`.
- Results and artifacts live at `prmpt-cli/harness/results/warm-session-20260628-165916/`.

Session semantics:

- Claude A used true resumed Claude sessions.
- Cursor used true resumed Cursor chats.
- Codex used true resumed Codex threads.
- PRMPT B/C used same-workspace sequential turns, but the current PRMPT CLI process is single-shot/in-memory, so it did not preserve one Pi SDK conversation across turns. This is important when interpreting B/C against the raw agents.

## Interpretation

The user's concern was valid: warm sessions reduce the penalty for raw agents because they can reuse learned repo context after turn 1.

But the results still show meaningful PRMPT savings:

- B retained perfect correctness and cut about one-third of Claude's token use.
- C cut about two-thirds of Claude's token use, but became less reliable.
- Cursor was fastest and perfect, but did not materially reduce tokens vs Claude.
- Codex was perfect but extremely token-heavy in this setup.

Harsh read: **B is the commercially safer default. C is promising as a cheaper/aggressive mode, but it needs reliability work before it should be the default.**
